## 自动推进模式。?agh-run→ 
用户可通过 `/agh-run` 启动全流程自动推进模式，等效于依次执行clarify → propose → apply → archive，但无需在阶段间手动输入命令。。
- 阶段间自动衔接，消除手动触发等待（实测节省约 5 分钟）?- 阶段内所有人工审批节点（★标记）照常暂停
- 支持断点恢复杂。state.md → `auto_advance: true`→ - 各阶段独立命令（/agh-clarify）?agh-propose→ agh-apply→ agh-archive）仍可单独使用
推进触发条件。。
| 完成标记 | 自动推进动作 |
|---------|------------|
| INIT-DONE | → propose 阶段 |
| PROPOSE-DONE / SR1 通过 | → apply 阶段 |
| SR3-DONE | → archive 阶段 |
| phase=done | 打印最终摘要，流程结束 |

## 各阶段详细执行序列
各阶段的详细步骤定义在对照skill 文件中（执行权威）：

| 阶段 | 执行权威文件 | 概要 |
|------|------------|------|
| clarify | skills/agh-clarify.md | 场景检查+ 环境预检 + 需求澄清+ 产出类型选择 + 模式选择 + Proposal 定稿 |
| propose | skills/agh-propose.md | BA需求。?SA设计 → TE用例 → PM编排 → SR1（按 mode 裁剪）?|
| apply | skills/agh-apply.md | DE开发芽?TE审计（test_strategy 驱动）→ 修复循环 → SR2 → SR3（按 mode 裁剪）?|
| archive | skills/agh-archive.md | 需求归档。?设计归档 → 产出物归档（output_type 感知）→ SR4（含 merge 策略）?|
| run | skills/agh-run.md | 全流程自动推进（）?fast 连续流） |
| ppt | skills/agh-android-game.md | output_type=ppt 补充规则（UX wireframe + verify-ppt.sh）?|

> Skills 文件。?Agent 的唯一执行依据。本文档仅作为人类阅读的流程参考。。
